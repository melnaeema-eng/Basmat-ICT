BASMAT ICT — MFA RECOVERY RESET FIX
=====================================

THIS FIX ADDRESSES THE CONFIRMED PROBLEM:
Email OTP succeeds, but the old Authenticator factor was not actually removed.

ROOT CAUSE FIXED:
The Admin listFactors result is read from data.factors.
The previous recovery function was reading data.totp / data.phone.

NO SQL.
NO DATABASE CHANGE.
NO FRONTEND CHANGE.

INSTALL:
cd C:\projects\Basmat-ICT

Expand-Archive -Path "$env:USERPROFILE\Downloads\Basmat-ICT-MFA-Recovery-RESET-FIX.zip" -DestinationPath . -Force

DEPLOY:
npx supabase functions deploy mfa-recovery --use-api

TEST:
1. Login with email + password.
2. At /admin/mfa click "فقدت رمز المصادقة؟".
3. Enter the email OTP.
4. The function now:
   - lists the account factors from data.factors
   - finds TOTP factor(s)
   - deletes each TOTP factor server-side
   - lists factors AGAIN
   - refuses to return SUCCESS unless remaining TOTP = 0
5. Login again.
6. /admin/mfa must now enter ENROLL mode and show a NEW QR.
7. Scan the new QR and verify the new Authenticator code.

IMPORTANT:
If Supabase still reports a remaining TOTP factor, the function returns an ERROR
instead of falsely saying that the reset succeeded.
